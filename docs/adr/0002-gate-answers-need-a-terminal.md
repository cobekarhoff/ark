# Human answers require an OMP ask or a controlling terminal

For a caller in OMP, an answer counts only when the bound main session contains the exact `ask` tool call and successful result for that run, action, packet hash and fixed answer choices. The CLI binds the main session id and transcript path on every `ark run start` and resume from a main session; a subagent, recognised by the `session_init` entry OMP writes only into its transcript (`parentSession` alone is no sign: forks have it), never rebinds, and a relaunched OMP session takes over the binding. The transcript is a tree (`/tree` navigation, re-answered asks and branch summaries leave abandoned entries in the file), so only the active branch counts, found with OMP's own leaf rule; the newest ask call on it with the identical question must have one successful result that selects the requested answer with no custom input, note, cancellation or timeout (a newer ask that was cancelled, redirected to chat or has no result yet refuses; an older answer never comes back). OMP writes a transcript lazily, so a session whose transcript is not on disk yet binds only while nothing is bound, and a bound transcript that holds a `session_init` proves nothing. And a consumed result stays consumed in a fork or relaunched session. A consumed ask result cannot answer another action. Hidden answer tools are only a transport: they cannot create this proof.

The rule covers gate answers (`gate.answered:<gate>`), run closes (`run.closed`, bound to the close packet hash of the opened MR list) and a human implementer step after `take_over` (`implementer.completed:<repo>`, answer `confirm`, bound to the worktree HEAD hash). The question text is `Ark <action> for run <run_id>; packet <sha256>. Choose exactly one: <choices>.`, asked single-choice with no `recommended` option. On a timeout OMP selects the recommended option, or the first option when none is recommended (`ask.ts` `getAutoSelectionOnTimeout`), so the protection is the `timedOut` refusal, not the absence of a recommendation. The recorded event carries `channel`, `session_id` and `ask_call_id`.

Only a caller without an OMP session id may use `/dev/tty`, and it is a second factor after the matching main-session ask proof has been found. Missing or malformed proof refuses everywhere. An OMP process with stale, reused, custom-input, cancelled or timed-out ask proof refuses rather than falling back to a terminal; otherwise an agent could allocate a PTY and answer without a human decision in OMP.

The ledger lock is held only after confirmation; Ark rechecks the packet, state and provenance under the lock before recording. This detects missing, stale, reused and malformed evidence and accidental transcript changes. As documented in ADR 0003, v1 trusts the user's own processes and does not defend against deliberate same-user file rewriting.
