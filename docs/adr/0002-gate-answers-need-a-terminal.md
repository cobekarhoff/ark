# Human answers require an OMP ask or a controlling terminal

For a caller in OMP, an answer counts only when the bound main session contains the exact `ask` tool call and successful result for that run, action, packet hash and fixed answer choices. The CLI binds the main session id and transcript path when a run starts; the result must select the requested answer with no custom input, note, cancellation or timeout. A consumed ask result cannot answer another action. Hidden answer tools are only a transport: they cannot create this proof.

The rule covers gate answers (`gate.answered:<gate>`), run closes (`run.closed`, bound to the close packet hash of the opened MR list) and a human implementer step after `take_over` (`implementer.completed:<repo>`, answer `confirm`, bound to the worktree HEAD hash). The question text is `Ark <action> for run <run_id>; packet <sha256>. Choose exactly one: <choices>.`, asked single-choice with no `recommended` option, because OMP auto-selects a recommended option on timeout. The recorded event carries `channel`, `session_id` and `ask_call_id`.

Only a caller without an OMP session id may use `/dev/tty`, and it is a second factor after the matching main-session ask proof has been found. Missing or malformed proof refuses everywhere. An OMP process with stale, reused, custom-input, cancelled or timed-out ask proof refuses rather than falling back to a terminal; otherwise an agent could allocate a PTY and answer without a human decision in OMP.

The ledger lock is held only after confirmation; Ark rechecks the packet, state and provenance under the lock before recording. This detects missing, stale, reused and malformed evidence and accidental transcript changes. As documented in ADR 0003, v1 trusts the user's own processes and does not defend against deliberate same-user file rewriting.
