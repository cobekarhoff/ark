# Hub is a read-only live view

ADR 0008 let the hub steer agents by typing into Orca terminals. The hub grew views (Timeline, Metrics, Search, Projects) and notifications that Orca and Master Chief already cover, and a second path to steer work next to Master Chief. The human wants the hub small again.

ARK-284 amends this ADR with one exception, a focus action. The human wants to see what an agent did and to jump from the hub to that agent in Orca. Orca has no link to an agent page (its `orca://` scheme opens only skills, plugins and pairing), and `orca terminal switch --terminal <handle>` is the only way to focus a terminal.

ARK-480 amends it again with three writes, all on the Companions page. A companion is an always-on helper agent that proposes tickets and writes ideas (ARK-480). The human wants to approve or dismiss a proposal and to ask a companion a question where the proposal is, not by typing a command in Master Chief's terminal.

## Decision

- **The hub shows Home, Runs, Roadmap, Resources and Companions.** Resources (ARK-418) shows the host (CPU, memory pressure, swap, disk, load, the `ark test` admission) on a strip on every page, and a page that groups processes by run, agent, leftover and other. It reads `ps` and `lsof` and keeps a 24-hour history of each host signal in memory; `GET /api/resources/history` serves that history. A leftover process gets a button that copies `kill <pid>`; no route or button changes a process. Roadmap replaces Backlog: it shows the project's vision, milestones and ranked tickets from `ROADMAP.md`, and a ticket opens as a full page. Runs replaces Map: it shows every run on one board with a cross-run dependency graph, and a run opens as its own page. No Timeline, Metrics, Search or Projects view. The run page shows any run, open or closed: its decisions timeline, its files, and the transcript of each agent. Companions (ARK-480) lists the companions of `ark.yml` with their state (`running`, `retained`, `none`, or `unavailable` when Orca does not answer, never `stopped`), last wake, trigger and cost, and under them each companion's latest ideas (`companions/<name>/ideas.md`) and the tickets that name it in their `source` line. `GET /api/companions` serves it. Agent-written text is rendered as escaped text, never as HTML. The Roadmap Review list stays the one list of every proposed ticket.
- **The hub is read-only, with two exceptions: a focus action and the three writes of the Companions page.** No steering, no text sent into a terminal, no notifications. It never changes `state.json`, `events.ndjson` or a gate. It writes one run file: while a page is open it adds the `agents`, `gaps` and `sampled_until` keys of `results/resources.json` of each open run, by read, change and rename of that file, so `ark test`'s `suites` key stays. That file is a record of how much the run used, not run state.
- **The focus action is `POST /api/open-in-orca`** with `{ "terminal": <handle> }`. It runs `orca terminal switch --terminal <handle>` (an argument array, never a shell string) and nothing else. It sends no text into a terminal and changes no run state. It and the three companion routes are the hub's only routes that accept a POST; every other route answers a write method with 404 or 405, and each of these four answers every other method with 405. A body over 1024 bytes is refused with 413 on this route; the server takes up to 4096 bytes for the companion routes.
- **Only the hub's own page may use these four routes.** Each answers 403 unless the request's Origin and its Host are both `127.0.0.1:<port>` of the hub. A browser always sends Origin on a POST, so a request with no Origin is refused too (curl and scripts do not pass), and `localhost` is refused although the read routes accept it. The hub's own name, given with `--name`, counts as its own address (alone or with port 80, and Origin and Host must still match each other), and no other `*.localhost` name does. The focus route answers 400 when the body is not that JSON or the handle is not listed as live in the current snapshot, and 502 when `orca` fails or times out.
- **The three companion writes are `POST /api/companions/approve`, `/dismiss` and `/ask`.** Each takes a JSON body with `project` and `name`, and the name must be a companion of that project's `ark.yml`: the name selects a listed entry, and no path is built from a request value. _Approve_ (`id`) sets the `status:` line of a `proposed` ticket whose `source` names that companion to `ready`, with `setTicketStatus`, and does nothing else: it creates no Orca task and sends no message, and Master Chief queues the ticket. _Dismiss_ (`item`, `reason`) appends one entry with the item, the reason and the time to `companions/<name>/dismissed.md`, which the companion reads before it proposes again; the ticket stays `proposed` and is marked dismissed. _Ask_ (`question`, optional `item`) runs `ark companion ask`, which sends the companion's worker one message and needs Orca. A reason or a question must not be empty and has at most 400 characters, counted in characters and checked on the server. Each route has the origin check of the focus action: 403 unless Origin and Host are both the hub's own `127.0.0.1:<port>`, a missing Origin included. A refusal answers `{"error": ...}` with 400 (body, text), 404 (unknown project, companion, ticket or item), 409 (`ark.yml` does not load) or 502 (`ark companion ask` failed), and changes no file.
- **Agents carry `terminal` and `live`.** `live` is true when Orca lists the terminal as connected. A released agent stays in the snapshot with `live: false`; the page shows "ended, not in Orca" and no button.
- **A handler reads memory, asks the usage worker thread for one transcript page or one full tool result, reads one small run file or evidence file, reads one ticket file at request time, or reads one image.** The run file route serves the run's own documents (`plan.md`, `strategies.md`, `retro.md`, `ticket.md`, `evaluation.md`, and the files in `findings/` and `results/`) as text. The ticket route (`GET /api/ticket/<project>/<id>`) reads the one ticket file the hub listed for that id, never a path built from the URL, and answers its document as JSON; an unknown project or ticket answers 404. The run's test evidence, the test cases of a ticket and the evidence files of `results/evidence/` are read on request and sent as JSON text. The conversation routes (`GET /api/run/<run>/conversation`, `GET /api/conversation?since=&until=` and `GET /api/conversation/message/<id>`) answer from the last full inbox read, built in the usage worker thread: the run route carries bodies, the project route none, and the message route looks its id up in memory, never in a path. The image route (`GET /api/run/<run>/image?path=`) also serves image files (png, jpeg, gif, webp) under `results/evidence/` of the run's folder. It is GET only, rejects `..` before it joins a path, answers 404 for a real path outside the run folder (symlinks included) and for any file whose extension and first bytes are not an image, and serves an image with `x-content-type-options: nosniff`. Closed runs are read when the page asks and are never part of the snapshot. Transcript pages show tool calls with name, arguments (each string field cut at 20,000 characters), `ok` or `error` and the first line of the result. The full result of one call comes from `GET /api/run/<run>/transcript/result?file=&call=`: the usage worker thread scans the session file (the same transcript slot as page reads) and the route answers `{text, size, cut}` cut at 64,000 characters. It answers 404 for a file that is not one of the run's session files, an unknown call and a call with no result yet.
- **Master Chief stays the only path to queue or steer work.** The human talks to Master Chief in its Orca terminal, as ADR 0004 and ADR 0005 say. Approving a companion's ticket only marks it `ready`; Master Chief queues it, after the evaluation it runs for every ticket (`skills/ark-chief/SKILL.md`). A companion's ask goes to the companion, whose answer goes to Master Chief.

## Considered options

- Keep steering from the hub (ADR 0008): a second path next to Master Chief, and a larger surface to keep correct.
- Keep the extra views: each one repeats data Orca or Master Chief already gives.
- No action at all: the human then finds an agent in Orca by hand.
- Accept a request with no Origin on the focus route: keeps curl simple, but turns the one POST into a route any local process or DNS-rebinding page can call.
- Let the page approve through Master Chief only (a message the human types): the human then leaves the proposal to answer it, and a dismissal with a reason has no place to go that the companion reads.
- Have approve also create the Orca task (`task-create`): it skips the evaluation that Master Chief runs on every ticket before it queues one.

## Consequences

- ADR 0008 is superseded in part: its steering is gone. Its name "hub" and one Master Chief per project stay. ADR 0007's three-tools split stays.
- The hub has no `orca terminal send` code. Its calls to Orca that act are `orca terminal switch` and, through `ark companion ask`, one `orca orchestration send` to a companion's worker. It never creates or stops a worker and never queues a task.
- Transcripts are session files that the same OS user can already read (ADR 0004). The hub serves only `127.0.0.1` and does not redact them.
- An Orca feature request for an `orca://terminal/<handle>` link is filed outside Ark. When it ships, the route can go.
