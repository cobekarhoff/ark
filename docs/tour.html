Ark, step by step

A run takes a ticket to merge requests that carry their own proof. Click a step to see who acts, which command runs, which phase ark status shows and what you are asked. On GitHub an MR is a pull request.

Nothing here is live. The run folder files are excerpts from one real run on the Ark repo, 2026-11-12-ARK-426-1. The simulator and the dependency-chain and hand-off tabs show the shape of a run on a made-up project; their names are illustrative.

  • amber = waits for you
  • teal = an agent
  • grey = the ark command

Master Chief (one per project) starts run leads (one per ticket). A run lead starts workers. A worker starts nobody.

Steps of a run, with the phase ark status shows

Amber steps wait for you: the criteria, the strategy cards (only with two or more), the plan, an escalation, and your merge. A manual check also waits for you, inside building. Between them the run goes by itself, under a round budget. The ark command keeps the transition table, so a run cannot reach building before the plan is approved.

The run folder

Everything a run did is a file under ~/.ark/projects/<project>/runs/<run>/. The event log is the record; the rest is derived or written by an agent. These are excerpts from run 2026-11-12-ARK-426-1, shortened with ….
