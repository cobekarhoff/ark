## Objective

Prove that `.github/workflows/ci.yml` runs the Bun suite as 4 parallel shard jobs balanced by the committed timings file plus one hub timing job that runs the files the shards ignore with no `--parallel`, that the shards and the hub timing job together run each test file on disk exactly once, and that a final job named `test` fails when any shard, the hub timing job or the static-checks job fails, is cancelled or is skipped. Serves ARK-571/AC1. ARK-630 moved the hub timing files out of the shards; its AC1 is inspection and its AC2 a CI demonstration, so this case is their guard, not their proof.

The authoring gate:

1. The contract is the merge gate: which files run in which job, and which check name the branch protection waits for (`contexts: ["test"]`). The files and the check name are observable on the real workflow, the real timings file and the real Bun.
2. Regressions that fail it: a shard selection that leaves a disk `test/*.test.ts` file in no job or in two; a `--path-ignore-patterns` path in the shard step that the hub timing job does not run, or a hub timing path that the shards also run; a hub timing file renamed or deleted while the workflow still names the old path (Bun 1.4.4 exits 0 on a missing path argument, `evaluation.md`); a shard step whose `--path-ignore-patterns` flags replace the `bunfig.toml` `pathIgnorePatterns` (probed on Bun 1.4.4: `bun test --path-ignore-patterns=test/b.test.ts` in a scratch folder whose bunfig ignores `test/pw/**` listed `test/a.test.ts` and `test/pw/x.test.ts`); `--parallel` or `--shard` on the hub timing step; a timings entry for a deleted file; an empty committed timings map; `--shard=N/3` with a matrix of 4; a matrix job named `test`; an aggregate job with `needs` that leaves out the static-checks job, the shard job or the hub timing job; no `if: always()`; a line that treats `skipped` or `cancelled` as pass; a `continue-on-error: true` on a job; a `paths:` filter under `pull_request`. A new file with no timings entry is not a regression: Bun places it once (Step 7).
3. One contract, one owning case: this case owns the file layout of the CI jobs, the aggregate and the triggers. `test/ci-bun-pin.test.ts` (ARK-T570) reads only the pins of every job that runs bun; `test/playwright-workers.test.ts` (ARK-T698) reads only the Playwright job. No other test reads the shard or hub timing steps.
4. No test-only export, flag or hook. The real `ci.yml` is parsed with `Bun.YAML.parse` (as ARK-T570 does). The file list comes from the disk, never from the timings file or from the workflow. Each shard and each hub timing entry is observed with the real `bun test` and the exact flags of its step, in a listing form that runs no test (Step 4). The aggregate step is the real shell line of `ci.yml`, run with `bash`. GitHub itself is not run: that the runner expands `needs.*.result` and `matrix.*` is the platform's contract, and ARK-630/AC2 (demonstration) covers the real runs.

Out of scope: the wall time of the jobs (ARK-571/AC3, ARK-630/AC2); the how-to text (inspection); Playwright (ARK-T698); the Bun pin of each job (ARK-T570); that the repo's branch protection lists `test` (a human step; the case proves only that a job named `test` exists and cannot be a matrix); the names of the hub timing files (ARK-630/AC1, inspection: the case proves that the job and the shard step name the same existing files, not which ones).

## Preconditions

- The real `.github/workflows/ci.yml`, the timings file that the shard step names in `--timings=`, `bunfig.toml`, and the real test files of the repo at the head under test.
- Bun at the pinned version; `bash` on the host. No network, no Playwright browser, no GitHub.
- For Step 7 a scratch folder with 9 `test/f<n>.test.ts` files (each one passing `expect(1).toBe(1)`), a timings file that lists 8 of them and also lists a tenth path that has no file, a `bunfig.toml` with the `pathIgnorePatterns` value of the repo's `bunfig.toml` (and no preload), a passing `test/pw/ignored.test.ts`, and a passing test file at each hub timing path (Step 2).

## Steps

1. Parse `ci.yml`. Read `on`: `push.branches` and `pull_request`.
2. Find the jobs by what they run, not by their order: the shard job is the job whose `bun test` step carries `--shard=`; the hub timing job is the job, other than the shard job, whose steps run `bun test`; the static-checks job runs `bun run typecheck`, `bun run lint` and `bun run format:check`; the aggregate job is named `test`. Read the shard job's matrix values and its `bun test` step with its `--shard`, `--timings` and `--path-ignore-patterns` flags. The hub timing paths are the `--path-ignore-patterns` values of the shard step that are not a `pathIgnorePatterns` value of `bunfig.toml`. Read the hub timing job's matrix entries and its `bun test` step.
3. Read the timings file named by `--timings`: `version`, and each path in `files`. Build the expected file set from the disk: every `*.test.ts` under the repo root, skipping `node_modules` and the `pathIgnorePatterns` of `bunfig.toml` (`test/pw/**`).
4. For each shard matrix value `n`, run the real `bun test` with the step's flags (the `${{ matrix.shard }}` expression replaced by `n`, `--parallel` dropped) plus `--test-name-pattern` of a string that matches no test and `--reporter=junit --reporter-outfile=<scratch>/<n>.xml`, so Bun selects the shard's files, loads them and runs no test (a non-zero exit with "matched 0 tests" is expected). Read the `<testsuite name="....test.ts">` entries of each report as that shard's files (describe blocks add other `testsuite` entries; skip those). Record also the `--shard=n/T: running k/N test files` line.
5. For each hub timing matrix entry, run the real `bun test` of the hub timing step with each `${{ matrix.<key> }}` expression replaced by the entry's value, in the listing form of Step 4. Read each entry's files.
6. Run the aggregate step. Take the `run` line of the aggregate job and run it with `bash -e`, with the `needs.<job>.result` expressions (or a `join(needs.*.result, ...)` expression) replaced by a value, for these inputs: all needed jobs `success`; for each needed job in turn (the static-checks job, the shard job and the hub timing job; a matrix job's result is the one value GitHub reduces from its entries, so a failed or a cancelled entry reaches the line as `failure` or `cancelled`) `failure`, with the others `success`; for each in turn `cancelled`; for each in turn `skipped`.
7. In the scratch folder, run Step 4's selection with the 4 shard values on the files and the timings file of the preconditions (8 files listed, 1 unlisted, 1 entry with no file, 1 file under `test/pw/`, 1 file at each hub timing path).

## Expected results

- Step 1: `push.branches` shall contain `main`, and `pull_request` shall be present with no `paths`, `paths-ignore` or `branches` key, so every PR runs the suite and a push to main runs it as well.
- Step 2: the shard matrix shall have exactly the 4 values 1, 2, 3, 4 (any order, any type that expands to 1..4); the `--shard` flag shall be `${{ matrix.shard }}/4`, so the total equals the matrix size; `--timings=` shall name one file that exists in the repo; the shard step shall carry at least one `--path-ignore-patterns` flag. The shard job shall not be named `test`, and shall run `bun install --frozen-lockfile` and `bunx playwright install --with-deps chromium` before `bun test`. The hub timing job shall exist, shall not be named `test`, shall run `bun install --frozen-lockfile` before `bun test`, and its `bun test` step shall carry no `--parallel` and no `--shard`. The shard job, the hub timing job and the static-checks job shall each have no `if:` and no `continue-on-error: true`. A job named `test` shall exist, shall have no `strategy`, and shall have `needs` equal to exactly the static-checks job, the shard job and the hub timing job (so the line reads three results), `if` containing `always()`, and no `bun`/`bunx` step (or one pinned like ARK-T570 requires).
- Step 3: the timings file shall have `version` 1, `files` shall have at least one entry (an empty map shall fail the case: no recorded durations supply the balance), every entry shall be a finite non-negative number of milliseconds and at least one shall be above 0, and every path in `files` shall be a file on the disk (an entry with no file shall fail the case and name the path; the file list is never taken from the timings file).
- Step 4 and 5: there shall be at least one hub timing path, and each shall be a file on the disk (a renamed or deleted hub timing file shall fail the case and name the path). The hub timing entries shall be pairwise disjoint and none shall be empty, and their union shall equal the set of hub timing paths exactly. The 4 shard lists and the hub timing lists shall be pairwise disjoint and their union shall equal the disk set exactly, so each file runs in one job once; no shard shall be empty; each `running k/N test files` line shall have k equal to the length of its list and N equal to the disk count minus the number of hub timing paths (at the base of ARK-630, `bun test --shard=1/4` with one `--path-ignore-patterns` flag for each of the four hub timing files printed `--shard=1/4: running 17/78 test files`, with 82 files on disk). The failure message shall name the file that has zero or two jobs.
- Step 6: for all `success`, the line shall exit 0. For each of the static-checks job, the shard job and the hub timing job at `failure`, `cancelled` or `skipped`, the line shall exit non-zero. A `skipped` result shall never pass.
- Step 7: the 4 lists shall be disjoint and their union shall be the 9 `test/f<n>.test.ts` files, with the unlisted file in exactly one shard; the entry with no file shall change nothing; `test/pw/ignored.test.ts` and each file at a hub timing path shall be in no shard. This proves Bun's placement of an unlisted file (the coverage check in Step 4 reads the disk, so a new file missing from the timings file is placed, not lost), and that the shard step keeps the bunfig ignore list: a CLI `--path-ignore-patterns` replaces it (the probe in the authoring gate), so the step must also name the bunfig pattern, and no `test/pw` test file exists in the repo to show it in Step 4.
